# Grok Reverse Proxy

**Локальный API для аккаунтов grok.com**

Chat Completions · Responses · SSE · Изображения · Пул аккаунтов

![Node.js](https://img.shields.io/badge/Node.js-22.16%2B-43853d?logo=node.js&logoColor=white)
![Runtime](https://img.shields.io/badge/Runtime-Patchright%20%2B%20Chrome-4285f4?logo=googlechrome&logoColor=white)
![Status](https://img.shields.io/badge/Status-experimental-e9a23b)

</div>

Прокси предоставляет HTTP API с форматом OpenAI Chat Completions и Responses поверх Web Gateway Grok. Каждый аккаунт работает в отдельном профиле Chrome. Сообщения отправляются по WebSocket, изображения загружаются HTTP-запросами, а пул переключает запрос на другой доступный аккаунт при подтверждённом ограничении.

**Веб-чата в проекте нет.** Используйте curl или клиент, поддерживающий этот набор API.

> **Статус:** экспериментальная реализация. Транспорт, парсер и переключение проверяются автоматическими тестами; сквозная проверка текущей версии с grok.com ещё не завершена. Изменения приватного протокола сайта или Castle provider могут потребовать обновления адаптера.

## Возможности

| Возможность | Поддержка |
| --- | --- |
| Chat Completions | Текстовые и мультимодальные `messages` |
| Responses | `input`, `instructions`, текст и изображения |
| Потоковые ответы | SSE через `stream: true` |
| Несколько аккаунтов | Изоляция профилей, выбор по кругу |
| Переключение при ограничении | Повтор того же запроса до начала получения текста |
| Несколько изображений | PNG, JPEG, WebP, GIF в base64 data URL |
| Авторизация | Последовательный ручной вход через отдельные окна Chrome |
| Журнал | `log.json` с событиями и общим ID запроса |

При обычных запросах **видимые окна Chrome не открываются**. Однако проект не является полностью безбраузерным: headless Chrome сохраняет cookies и TLS-контекст, а штатный Castle SDK сайта создаёт свежий токен. Видимый браузер используется при добавлении или обновлении аккаунта.

## Требования

- Linux и Node.js **22.16 или новее**.
- npm и установленный **Google Chrome stable**.
- Графическая сессия для первоначального ручного входа в аккаунты.
- Доступ к grok.com и аккаунты, в которые вы можете войти.

Зависимости фиксируются в `package-lock.json`. Дополнительно устанавливать браузер Playwright не требуется: по умолчанию используется системный Chrome, `channel: chrome`.

## Быстрый старт

```bash
git clone https://github.com/PRISSET/reverse_proxy_grok.git
cd reverse_proxy_grok
npm ci
cp .env.example .env
npm run accounts -- login account1 account2
npm start
```

Скрипт входа откроет Chrome для первого аккаунта. Войдите в Grok, завершите проверки сайта и нажмите **Enter в терминале**. После сохранения скрипт закроет это окно и откроет профиль следующего аккаунта.

API запускается по адресу:

```text
http://127.0.0.1:8787/v1
```

Проверка процесса:

```bash
curl http://127.0.0.1:8787/health
```

При первом запуске сервер создаёт ключ в `.state/api-key`. Во втором терминале, из каталога проекта:

```bash
export GROK_LOCAL_KEY="$(cat .state/api-key)"
```

Если вы задали собственный `GROK_PROXY_KEY` в окружении или `.env`, используйте его вместо содержимого файла.

## Добавление аккаунтов

### Один аккаунт

```bash
npm run accounts -- login account1
```

### Несколько аккаунтов подряд

```bash
npm run accounts -- login account1 account2 account3
```

ID — локальная метка, а не адрес почты. Допускаются 1–64 латинских буквы, цифры, `_` и `-`; первый символ — буква или цифра. Для каждого ID создаётся отдельный профиль. В каждый профиль войдите в нужный аккаунт самостоятельно.

1. Откройте страницу входа в появившемся Chrome.
2. Введите данные аккаунта на сайте и завершите авторизацию.
3. Вернитесь в терминал и нажмите Enter.
4. Дождитесь сообщения `СОХРАНЕНО` и завершения закрытия Chrome.
5. Повторите действия для следующего ID.

**Не нажимайте «Выйти» на сайте после сохранения:** это может отозвать авторизацию. Скрипт сам закрывает отдельный браузер без logout. Пароли не передаются через командную строку.

### Просмотр сохранённых аккаунтов

```bash
npm run accounts -- list
```

`ready` означает, что вход был подтверждён и сохранён. Текущее состояние пула, занятость и время окончания паузы доступны через `/status`.

### Обновление истёкшего входа

Остановите сервер, затем повторите вход с тем же ID:

```bash
npm run accounts -- login account2
npm start
```

Остальные профили сохраняются. Не открывайте один профиль одновременно через сервер и скрипт входа.

### Восстановление после зависания или аварийного завершения

Остановите старый процесс и закройте его окно Chrome:

```bash
npm run accounts -- recover account3
npm run accounts -- login account3
```

`recover` проверяет процесс-владелец и Chrome, затем снимает только устаревшую блокировку приложения. Активный процесс блокирует восстановление. Профили, cookies и блокировки самого Chrome не удаляются. Команду выполняйте в обычном терминале той же машины.

После Enter проверка входа ограничена 20 секундами, чтение cookies и закрытие Chrome — 10 секундами каждое. Подтверждённая сессия записывается **до** закрытия браузера. При проблеме скрипт сообщает этап; ранее сохранённые сессии не удаляются.

## Использование API

Все маршруты, кроме `/health`, требуют:

```http
Authorization: Bearer <ключ прокси>
```

### Маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Состояние процесса, без проверки Grok |
| GET | `/status` | Аккаунты, занятость, паузы |
| GET | `/v1/models` | Локальный псевдоним `grok-web` |
| POST | `/v1/chat/completions` | Chat Completions |
| POST | `/v1/responses` | Responses |
| GET | `/log.json` | Журнал; поддерживает `?after=SEQUENCE` |

Для `/models`, `/chat/completions` и `/responses` доступны варианты без `/v1`.

### Обычный ответ

```bash
curl http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GROK_LOCAL_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "grok-web",
    "messages": [{"role": "user", "content": "Привет! Ответь коротко."}]
  }'
```

Текст находится в `choices[0].message.content`.

### Потоковый ответ

```bash
curl -N http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GROK_LOCAL_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "grok-web",
    "stream": true,
    "messages": [{"role": "user", "content": "Объясни, как работает WebSocket."}]
  }'
```

Успешный поток заканчивается `data: [DONE]`. При ошибке после начала потока отправляется ошибка без имитации успешного завершения.

### Responses

```bash
curl http://127.0.0.1:8787/v1/responses \
  -H "Authorization: Bearer $GROK_LOCAL_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "grok-web",
    "instructions": "Отвечай по-русски и по существу.",
    "input": "Чем HTTP отличается от WebSocket?",
    "store": false
  }'
```

Для SSE добавьте `"stream": true`. Текст ответа находится в `output[].content[]` с типом `output_text`.

### Продолжение разговора

Передавайте предыдущие реплики в `messages`. История преобразуется в текстовый транскрипт; это не нативная система ролей Grok. Параметры `previous_response_id` и сохранение Responses-сессий не поддерживаются.

`grok-web` — псевдоним режима `GROK_MODE`, по умолчанию `fast`, а не фиксированная версия модели. Поддерживаются текстовые роли `system`, `developer`, `user`, `assistant`.

**Границы совместимости:** tool calling, sampling-параметры, `max_tokens`, произвольные модели, внешние URL изображений и `file_id` не реализованы. Неизвестные параметры возвращают HTTP 400, а не игнорируются. Расход токенов и остаток квоты не вычисляются.

## Изображения

Изображения передаются как base64 data URL. Поддерживаются несколько частей `image_url` в пользовательском сообщении; в Responses — `input_image`.

Пример для двух PNG-файлов в текущем каталоге, без дополнительных библиотек:

```bash
node --env-file-if-exists=.env --input-type=module <<'JS'
import { readFile } from 'node:fs/promises';
const key = process.env.GROK_PROXY_KEY || (await readFile('.state/api-key', 'utf8')).trim();
const images = await Promise.all(['first.png', 'second.png'].map(async filename => ({
  type: 'image_url',
  image_url: { url: `data:image/png;base64,${(await readFile(filename)).toString('base64')}` },
})));
const response = await fetch('http://127.0.0.1:8787/v1/chat/completions', {
  method: 'POST',
  headers: { Authorization: `Bearer ${key}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({
    model: 'grok-web',
    messages: [{ role: 'user', content: [{ type: 'text', text: 'Сравни изображения' }, ...images] }],
  }),
});
console.log(response.status, await response.text());
JS
```

Для JPEG, WebP или GIF укажите соответствующий MIME. Локальные ограничения: **8 изображений**, **10 MiB на файл**, **32 MiB на весь JSON-запрос**. Ограничения самого Grok могут быть строже.

Файлы загружаются через HTTP multipart; их идентификаторы прикрепляются к WebSocket-сообщению. При переключении аккаунта изображения загружаются заново из исходных байтов, а чужие файловые ID не переиспользуются.

## Переключение аккаунтов

Пул выбирает готовые аккаунты по кругу. Один профиль обслуживает один активный запрос; разные аккаунты могут работать параллельно.

```text
Запрос → доступный аккаунт → свежий Castle-токен → HTTP / WebSocket
                             │
                             ├─ Ответ → клиент
                             └─ Подтверждённый rate limit → пауза → следующий аккаунт
```

- При HTTP 429 или распознанном коде ограничения аккаунт получает паузу. Используется срок сервиса, если он передан; иначе `GROK_COOLDOWN_MS`.
- До первого фрагмента текста тот же запрос можно перенести на следующий аккаунт.
- После получения текста автоматического повтора нет, чтобы не создавать дубликаты.
- При истёкшей авторизации профиль помечается `auth_required` и выбирается следующий.
- Неизвестные ошибки, сбои Castle и сетевые отказы не выдаются за rate limit.
- Если все аккаунты ограничены, возвращается 429 с `Retry-After`; если все заняты или не готовы — 503. Очереди ожидания нет.

## Настройки

Задавайте значения в `.env` или окружении процесса. Пример — [`.env.example`](.env.example).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `8787` | Порт; сервер слушает `127.0.0.1` |
| `GROK_PROXY_KEY` | Генерируется | Bearer-ключ локального API |
| `GROK_STATE_DIR` | `.state` | Каталог аккаунтов и состояния |
| `GROK_LOG_FILE` | `log.json` | Путь к журналу |
| `GROK_CHROME_CHANNEL` | `chrome` | Канал установленного Chrome |
| `GROK_MODE` | `fast` | Режим gateway за псевдонимом `grok-web` |
| `GROK_LOCALE` | Из ОС | Язык, сохраняется при создании профиля |
| `GROK_TIMEZONE` | Из ОС | Часовой пояс профиля |
| `GROK_TIMEOUT_MS` | `180000` | Срок выполнения запроса после запуска браузерного контекста |
| `GROK_COOLDOWN_MS` | `300000` | Резервная пауза после ограничения |
| `GROK_DONE_EVENT` | `response.done,response.completed` | Терминальные события gateway |

Язык, часовой пояс и канал должны соответствовать сохранённому `browser-profile.json`. Авторизация оконная; запросы всегда headless. Старый `GROK_HEADLESS=false` не включает окна при генерации.

## Сессии и журнал

```text
.state/
├── api-key
└── accounts/
    ├── account1/
    │   ├── account.json
    │   ├── browser-profile.json
    │   ├── session-cookies.json
    │   └── profile/
    └── account2/
        └── ...
log.json
```

`profile/` содержит штатные данные Chrome, включая HttpOnly-cookies. `session-cookies.json` дополнительно сохраняет сессионные cookies Grok, которые могут не пережить перезапуск браузера. Этот файл содержит секретные значения; права — 0600, каталог состояния — 0700.

Авторизуйтесь на той же машине и под тем же пользователем ОС, где будет работать прокси. Перенос профиля на другую машину может не восстановить вход из-за системного шифрования Chrome. При работе без графического сеанса генерация headless возможна, но первоначальный вход требует GUI.

`log.json` хранит последние **2000 событий**: выбор аккаунта, ограничение, паузу, переключение и результат. Общий `request_id` связывает попытки; `from_account` и `to_account` показывают переход. При ошибке может записываться этап `navigation`, `castle`, `gateway` или `response`.

```bash
curl http://127.0.0.1:8787/status \
  -H "Authorization: Bearer $GROK_LOCAL_KEY"

curl http://127.0.0.1:8787/log.json \
  -H "Authorization: Bearer $GROK_LOCAL_KEY"
```

Тексты сообщений, ответы, изображения, cookies и Castle-токены в журнал не записываются. `.state/`, `.env`, журнал и отладочные артефакты исключены из Git.

## Диагностика

| Код | Действие |
| --- | --- |
| `auth_required` | Остановить прокси и повторить `accounts -- login ID` |
| `account_busy` | Закрыть процесс, использующий профиль; при устаревшей блокировке — `recover ID` |
| `browser_driver_missing` | Выполнить `npm ci` |
| `browser_unavailable` | Проверить установку Chrome, доступность профиля и окружение входа |
| `browser_profile_mismatch` | Сверить канал, язык, пояс и ОС с сохранёнными параметрами |
| `castle_sdk_unavailable` | Проверить соответствие Castle-адаптера текущей сборке Grok |
| `browser_api_mismatch` | Проверить сигнатуру драйвера; main-world вызов имеет вид `evaluate(fn, arg, undefined, false)` |
| `gateway_handshake_timeout` | Проверить доступность WebSocket и актуальность протокола |
| `upload_failed` | Проверить формат файла и HTTP-протокол загрузки |
| `upstream_timeout` | Проверить сеть, завершающее событие и журнал |

Для сопоставления записи журнала с запросом используйте заголовок ответа `X-Request-Id`. Можно передать собственный `X-Request-Id`: до 80 латинских букв, цифр, `_` или `-`.

## Разработка

```bash
npm run check
npm test
```

Проверки охватывают HTTP-обработчик, авторизацию API, SSE, вход и тайм-ауты, блокировки профилей, сохранение cookies, HTTP/WS-транспорт, парсер ответа и переключение аккаунтов. Внешний Grok в тестах заменён серверными фикстурами; успешные тесты не подменяют живую интеграционную проверку.

```text
src/
├── accounts.mjs             # CLI управления аккаунтами
├── account-login.mjs        # Вход и сохранение до закрытия Chrome
├── worker.mjs               # Фоновый транспорт аккаунта
├── gateway-request.mjs      # HTTP-загрузка и WebSocket gateway
├── castle-provider.mjs      # Доступ к SDK сайта
├── protocol.mjs             # Разбор событий
├── pool.mjs                 # Маршрутизация и паузы
├── audit.mjs                # Безопасный JSON-журнал
├── api.mjs                  # HTTP API и SSE
└── server.mjs               # Запуск сервера
```
